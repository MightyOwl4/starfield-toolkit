# Implementation Plan: Remove Creation (Disable + Delete)

**Branch**: `013-remove-creation` | **Date**: 2026-04-15 | **Spec**: [spec.md](./spec.md)

## Summary

Add a gated, single-Creation Remove action that strips the plugin from Plugins.txt and deletes its Files from the Data dir, reusing the existing game-running safety check pattern. Pure logic lives in a new `removal.py` module (fully testable without a GUI); the UI is a conditional button on the existing Creation details dialog plus a new Win+D-safe confirmation/result dialog.

## Technical Context

**Language/Version**: Python 3.12+
**Primary Dependencies**: customtkinter (GUI), standard library only for the removal logic
**Storage**: JSON settings file at `%APPDATA%/StarfieldToolkit/config.json`; Plugins.txt and Data dir on disk
**Testing**: pytest, `uv run pytest` — unit tests for pure logic, no tkinter in CI
**Target Platform**: Windows desktop (Starfield is Windows-only)
**Project Type**: Desktop app (single project, `src/starfield_tool/`)
**Performance Goals**: SC-001 — full Remove + list refresh in under 15 s for typical Creation sizes
**Constraints**: No admin/UAC, no transient()/grab_set() on dialogs, no mutation outside an explicit Confirm click
**Scale/Scope**: One Creation per invocation, ~1–5 files per Creation

## Key Design Decisions

1. **Separate pure logic from UI.** `removal.py` takes paths and a Creation, returns a plan, executes it — no tkinter imports. This is what makes US1–US5 testable without a display and satisfies principle II.
2. **Extract `is_starfield_running` once, now.** Currently lives on `LoadOrderTool._is_starfield_running`. Move to `game_process.py` and call from both tools. Also add `is_launcher_running()` for the Bethesda launcher (`BethesdaNetLauncher.exe` / `Starfield_BGS.exe` — confirmed in research).
3. **ContentCatalog.txt is not modified.** Matches the filter rule already committed in `parsers.build_creation_list`: ghost entries are hidden automatically once files are gone. Keeps scope small and avoids racing the Bethesda launcher which owns that file.
4. **Plugins.txt edit strips any line whose non-`*` filename matches a Creation plugin file, case-insensitively.** Handles both `*foo.esm` and `foo.esm` forms; the file is plain text with LF line endings per observation.
5. **Path safety.** Every file in `Files` is resolved against `data_dir` and checked that the resolved path is inside `data_dir` (defence against a ContentCatalog entry with `..`). Out-of-tree entries are refused in the plan phase, not the execute phase, so the confirmation dialog can show the refusal.
6. **Confirmation dialog pattern.** Follow the `load_order_diff.py` recipe: `CTkToplevel` + `attributes("-topmost", True)` + `after(100, ...)` flash-to-false; no `transient`, no `grab_set`. Centred via existing `center_dialog` helper. Explicit Cancel button plus `WM_DELETE_WINDOW` protocol both route to a cancel path that mutates nothing.
7. **Result dialog is a second Toplevel opened after execute completes.** Keeps the confirm dialog stateless (Confirm → spawn worker thread → on complete open result dialog on the main thread via `dlg.after(0, ...)`). Status bar shows the in-flight task.
8. **Gating.** `AppSettings.enable_dangerous_ops` defaults False. The Remove button is conditionally constructed (not merely hidden) in `creation_details.py` so there's no stale widget. The Settings UI gets one new checkbox near `beta_acknowledged`.
